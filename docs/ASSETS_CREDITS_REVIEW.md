# External Resources and Portfolio-Origin Review

This checklist is intentionally **incomplete until the team verifies it**. The 2026 Judging & Awards Guide (p. 3) requires all externally sourced code, text, images and other material — even free or open-source assets — in the submission References field, and permission for copyrighted materials.

| Asset / dependency | Attribution or license review needed | Current status |
|---|---|---|
| NASA POWER API and underlying historical climate records | NASA POWER provider, parameter, spatial/temporal metadata, dataset/API citation, website | API integrated; actual sample must be verified |
| NASA Space Apps challenge statement | Official Field Shift challenge URL | Source known; cite |
| Python FastAPI, Uvicorn, Pydantic, HTTPX and test packages | Exact package versions and licenses used at submission | Needs dependency version/rights review |
| Holographic landscape and calibration art | Creation history / any AI-generated assets; verify allowed usage and credits | **Needs human source and permissions review** |
| Illustrative rover, terrain, satellite animations | Portfolio source ownership and any third-party references | **Needs human review** |
| Water-drop synthesized audio | Code-generated effect; verify original code and third-party source dependencies | **Needs human review** |
| Pre-existing Phase 1–13 source and prior portfolio artifacts | Date of development, authors/contributors, event reuse permission | **Ask event organizers; disclose previous work** |
| Any crop requirements/soil claims | Local agronomy reference and scientific review | **Not yet verified** |
| Any external fonts, graphics, icons or logos | Exact fonts, licenses and image-credit provenance | **Needs review** |

`ASSET_REGISTER_SHA256.csv` provides file hashes for traceability, **not** legal provenance or permission. Before any official submission, replace unknowns with verified author, source URL, date, license and permission details.

The uploaded *Judging & Awards Guide* is included under `docs/reference_guide/` for reference. Its presence is not proof that the rest of the project meets every applicable rule.
