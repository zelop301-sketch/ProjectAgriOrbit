# Publish and NASA Submission Checklist (Phase 42)

- [ ] Confirm all team members' names, contributions, consent to public GitHub release, and ownership of shared work.
- [ ] Audit visual assets, GIFs, graphics, audio, fonts, logos and any AI-generated assets for ownership and permission. See `ASSETS_CREDITS_REVIEW.md`.
- [ ] Check for API credentials, personal information, hidden .env or local cache before pushing any local additions.
- [ ] Confirm NASA Space Apps rules on code developed before the hackathon and disclose any pre-existing portfolio work, if applicable.
- [ ] Record AI tools used where required by NASA Space Apps submission guidance.
- [ ] Review dependencies and their exact licenses. Do not add an open-source LICENSE until the team agrees on one.
- [ ] Save an authentic NASA POWER response on an internet-connected machine, including source URL, UTC retrieval time, units, cache state, payload hash, and quality gates.
- [ ] Label every screenshot and video showing synthetic test data as `SYNTHETIC — NOT NASA OBSERVATIONS`.
- [ ] Record clear scientific limitations: no farmer study, crop-yield validation, irrigation saving, or measured plot-scale rainfall.
- [ ] Publish repo as PUBLIC if judges must view it without sign-in; open the link in an incognito window to verify.
- [ ] Paste the PUBLIC GitHub repository URL into the NASA Space Apps Team Project page. Verify that the project is actually submitted by the event deadline (which follows the team owner/local event timezone).
